# kartinkomet

Telegram-бот для общего пула пикч и анекдотов: рандомная выдача, загрузка в личке, реакции, топ загрузчиков, личные достижения, мемные дуэли, погода и чистка дублей. Боевой runtime лёгкий: только зависимости, которые нужны самому боту.

[English README](README.en.md)

## Что это

`@kartinkomet_bot` живёт в Telegram-группах и каналах. Он берёт случайную картинку из общего пула по кнопке `🎲 Рандом` или команде `/pic`, достаёт случайный анекдот через `😂 Анекдот` или `/joke`, запускает дуэли пикч и анекдотов и считает вклад пользователей.

Бот не хранит сами изображения на сервере. Он сохраняет только Telegram `file_id` и `file_unique_id`, а физические файлы остаются на стороне Telegram.

## Главная идея

- в группах бот раздаёт пикчи, запускает дуэли, показывает статы и топ
- загрузка пикч идёт только в личке с ботом, чтобы Telegram Privacy Mode не ломал приём файлов
- пул общий: загрузили в личке, используете в любой группе
- анекдоты живут отдельно от пикч в `jokes.json`
- дубликаты отсекаются по `file_unique_id`
- текстовые баяны отсекаются по нормализованному тексту
- визуальные дубли можно чистить отдельным скриптом через `dHash`
- тяжёлые зависимости для визуальной чистки вынесены в отдельный maintenance-файл
- один пользователь может добавить до `1000` новых пикч в час
- один пользователь может поставить одну реакцию на картинку, но может перевыбрать
- `2 🖕🏻` удаляют пикчу или анекдот из пула народным судом
- топ и достижения показывают username без `@`, чтобы никого не тегать
- дуэли пикч и анекдотов не зависают навсегда: таймер обновляется, stale-состояния очищаются

## Команды

| Команда | Что делает |
| --- | --- |
| `/pic` | Отправить случайную пикчу |
| `/joke` | Отправить случайный анекдот |
| `/duel` | Запустить дуэль двух случайных пикч |
| `/jokeduel` | Запустить дуэль двух случайных анекдотов |
| `/weather` | Показать погоду в Малой Токмачке |
| `/menu` | Открыть основной пульт |
| `/upload_pidor` | Открыть загрузку в личке |
| `/upload_joke` | Открыть загрузку анекдотов в личке |
| `/done` | Завершить загрузку |
| `/cancel` | Отменить загрузку |
| `/stats` | Показать сводку по пулу, рандому, дуэлям и реакциям |
| `/me` | Показать ваш вклад и достижения |
| `/top` | Показать топ загрузчиков |
| `/count` | Показать количество пикч и анекдотов |
| `/mood` | Показать режим бота на сегодня |
| `/help` | Показать справку |

`/upload` намеренно нет. Slash-команды загрузки явные: `/upload_pidor` для пикч и `/upload_joke` для анекдотов.

Скрытые служебные команды:

- `/reset_stats` - сброс реакций, показов, дуэлей и памяти рандома, только для `ADMIN_USER_IDS`
- `/dedupe_user USER_ID` - чистка точных дублей конкретного пользователя, только для `ADMIN_USER_IDS`
- `/id` - показать Telegram user ID, не отображается в публичном меню команд

## Рандом

Рандом не выбирает тупо первый попавшийся элемент. Алгоритм:

1. Убирает картинки, недавно показанные в текущем чате.
2. Убирает глобально свежие выдачи.
3. Предпочитает картинки с меньшим числом показов.
4. Финально выбирает через `SystemRandom`.

Если пул большой, повторы становятся заметно реже. Если пул маленький, повторы возможны, но бот старается не крутить одну и ту же пикчу подряд.

Анекдоты используют такую же идею: бот хранит историю выдачи по чату, выбирает из менее показанных записей и не тащит один и тот же текст подряд, если в пуле есть выбор.

## Погода

`/weather` и кнопка `🌦 Погода` показывают текущую погоду только для Малой Токмачки.

Погодные данные берутся без API-ключа. Пользователь ничего не выбирает и не вводит город.

Ответ оформлен отдельной карточкой: температура, ощущается, состояние неба, дневной коридор, осадки и ветер. Чтобы бот не дёргал внешний API на каждый клик, погода кэшируется на `10` минут.

## Анекдоты

`/joke` и кнопка `😂 Анекдот` отправляют случайный текст из отдельного пула.

Как загрузить:

1. Откройте личку с `@kartinkomet_bot`.
2. Нажмите `📝 Анекдоты` или отправьте `/upload_joke`.
3. Отправляйте анекдоты текстом, по одному сообщению на штуку.
4. Завершите через `/done` или отмените через `/cancel`.

Правила:

- анекдоты хранятся отдельно в `jokes.json`
- картинки и анекдоты не смешиваются
- пустые сообщения и команды не добавляются
- дубли отсекаются по нормализованному тексту
- один пользователь может поставить одну реакцию, но может перевыбрать
- `2 🖕🏻` удаляют анекдот из пула
- `/reset_stats` обнуляет реакции, показы и память выдачи, но не удаляет сами анекдоты

## Дуэли анекдотов

`/jokeduel` и кнопка `😂 Дуэль` выбирают два случайных анекдота и открывают голосование на `2` минуты.

Правила такие же, как у пикчевой арены:

- в одном чате может идти только одна активная дуэль любого типа
- каждый пользователь голосует один раз, но может перевыбрать сторону
- тексты анекдотов отправляются отдельными цитатами перед голосованием
- анекдоты не обрезаются: длинный текст дробится на несколько сообщений, но сохраняется полностью
- победитель остаётся в `jokes.json`
- проигравший анекдот удаляется из пула
- при ничьей оба анекдота остаются
- после итогов появляется кнопка `😂 Новая дуэль`

## Загрузка пикч

Надёжный сценарий:

1. Откройте личку с `@kartinkomet_bot`.
2. Нажмите `📥 Пикчи` или отправьте `/upload_pidor`.
3. Отправьте одну пикчу, пачку, альбом или пересланные изображения.
4. Нажмите `✅ Закончить` или отправьте `/done`.

В группе кнопка `📥 Пикчи` не включает приём файлов. Она объясняет, что заливать нужно в личке.

Бот не пишет отбивку на каждую картинку. После первой принятой пикчи он один раз показывает короткую инструкцию с кнопками завершения и отмены.

Учитываются:

- успешно добавленные пикчи
- дубликаты
- невалидные файлы
- лимит `1000` новых пикч в час на пользователя

## Дуэли

`/duel` выбирает две случайные пикчи, отправляет их альбомом без подписей и открывает голосование на `60` секунд.

Правила:

- в одном чате может идти только одна активная дуэль любого типа
- каждый пользователь голосует один раз, но может перевыбрать сторону
- карточка дуэли обновляет счёт и таймер
- победитель остаётся в пуле
- проигравшая пикча удаляется
- при ничьей обе пикчи выживают
- после итогов появляется кнопка `⚔️ Новая дуэль`
- если Telegram/API споткнулся, бот очищает зависшую дуэль и не блокирует чат

Карточка дуэли держит короткую структуру: заголовок, статус, счёт в одну строку и отдельный таймер. Картинки в альбоме идут без подписей, чтобы экран не превращался в кашу.

Внутри есть `400` коротких фраз для дуэлей:

- `100` заголовков старта
- `100` live-статусов
- `100` фраз победы
- `100` фраз ничьи

## Реакции и народный суд

Под каждой пикчей есть `🤙🏻` и `🖕🏻`.

Правила:

- один пользователь = один голос на одну картинку
- голос можно изменить
- голоса разных пользователей складываются
- повторное нажатие той же реакции не накручивает счётчик

Народный суд:

- `1 🖕🏻` - бот молчит
- `2 🖕🏻` - пикча или анекдот удаляется из пула, сообщение об удалении отправляется ответом на исходное сообщение

## Достижения и профиль

`/me` показывает:

- сколько пикч загрузил пользователь
- текущее достижение
- реакции на его пикчи
- показы его пикч
- титул качества
- комбо-достижения
- прогресс до следующего рубежа

Достижения выдаются автоматически на порогах загрузки. В сообщениях username пишется без `@`, чтобы не тегать человека.

## Текстовые пулы

Все фразы лежат в `bot/texts.py`.

Сейчас внутри:

- `1500` caption-фраз для случайных пикч
- `150` стартовых фраз загрузки
- `150` фраз завершения загрузки
- `150` фраз пустого пула
- `50` достижений
- `400` коротких фраз для дуэлей
- отдельные фразы для дуэлей анекдотов
- ежедневные mood-режимы
- тексты народного суда

Caption под пикчами чистый, без mood-приставок.

## Хранение

Пикчи и анекдоты хранятся в разных JSON-файлах.

Пикчи лежат в `image_pool.json`. Файл автоматически мигрирует со старого списка `file_id` на версионированный формат.

Пример:

```json
{
  "version": 3,
  "images": [
    {
      "id": "a1b2c3",
      "file_id": "AgACAgIAAxkBA...",
      "file_unique_id": "AQAD...",
      "added_by": 123456789,
      "added_at": "2026-04-25T13:00:00+00:00",
      "shown_count": 3,
      "last_shown_at": "2026-04-25T13:10:00+00:00",
      "likes": 1,
      "dislikes": 0,
      "reactions_by_user": {
        "123456789": "like"
      }
    }
  ],
  "chat_history": {
    "-1001234567890": ["a1b2c3"]
  },
  "users": {},
  "duel_stats": {
    "total": 37,
    "executions": 29,
    "ties": 8
  }
}
```

Анекдоты лежат в `jokes.json`:

```json
{
  "version": 1,
  "jokes": [
    {
      "id": "j1",
      "text": "Анекдот одной строкой или несколькими строками",
      "normalized_text": "анекдот одной строкой или несколькими строками",
      "added_by": 123456789,
      "added_at": "2026-04-29T13:00:00+00:00",
      "shown_count": 2,
      "last_shown_at": "2026-04-29T13:10:00+00:00",
      "likes": 1,
      "dislikes": 0,
      "reactions_by_user": {
        "123456789": "like"
      }
    }
  ],
  "chat_history": {
    "-1001234567890": ["j1"]
  }
}
```

## Производительность и надёжность

- пул читается в память один раз при запуске
- поиск картинки по `id` работает через индекс
- проверка дублей по `file_unique_id` работает через set
- счётчики загрузок пользователей берутся из индекса
- статистика пользователя берётся из индекса записей по user ID
- лимит загрузок в час считается по отсортированному индексу времени
- пары для дуэлей выбираются отдельными методами и сохраняют показы одной записью в JSON
- `Pillow` не входит в боевые зависимости Railway и нужен только maintenance-скрипту
- реакции нормализуются при чтении базы
- запись JSON атомарная, через временный файл
- завершение дуэли пикч удаляет проигравшую пикчу и пишет статистику одним сохранением
- завершение дуэли анекдотов удаляет проигравший текст из `jokes.json`
- stale-дуэли очищаются при следующей попытке запуска
- ошибки Telegram API логируются и не роняют polling

## Чистка дублей

Точные дубли конкретного пользователя:

```text
/dedupe_user 1045485205
```

Визуальные дубли через maintenance-скрипт:

```bash
pip install -r requirements-maintenance.txt
python scripts/visual_dedupe.py --user-id 1045485205 --dry-run
```

Применить после проверки отчёта:

```bash
python scripts/visual_dedupe.py --user-id 1045485205 --apply
```

Скрипт создаёт backup рядом с `image_pool.json`. Запускать лучше разово на Railway и не во время активного наплыва пользователей.

## Локальный запуск

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

`.env`:

```env
BOT_TOKEN=123456:your-token
IMAGE_POOL_PATH=data/image_pool.json
JOKE_POOL_PATH=data/jokes.json
TARGET_CHANNEL_ID=
ADMIN_USER_IDS=
```

Запуск:

```bash
python -m bot
```

Проверки:

```bash
python -m compileall bot scripts tests
python -m unittest discover
```

Для визуальной чистки дублей дополнительно:

```bash
pip install -r requirements-maintenance.txt
```

## Railway

В проекте есть:

- `Procfile` - запускает `python -m bot`
- `.python-version` - Python `3.12`

Railway variables:

```env
BOT_TOKEN=токен_бота
TARGET_CHANNEL_ID=
ADMIN_USER_IDS=ваш_telegram_user_id
```

Для постоянного хранения подключите Railway Volume с mount path:

```text
/data
```

Если `RAILWAY_VOLUME_MOUNT_PATH` есть, бот хранит пул тут:

```text
/data/image_pool.json
/data/jokes.json
```
