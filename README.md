# kartinkomet

Telegram-бот для общего пула пикч и анекдотов: рандомная выдача, загрузка в личке, реакции, топ загрузчиков, личные достижения, мемные дуэли, турниры, погода и чистка дублей. Боевой runtime лёгкий: только зависимости, которые нужны самому боту.

[English README](README.en.md)

## Что это

`@kartinkomet_bot` живёт в Telegram-группах и каналах. Он берёт случайную картинку из общего пула по кнопке `🎲 Пикча` или команде `/pic`, достаёт случайный анекдот через `😂 Анекдот` или `/joke`, запускает дуэли, мини-турниры и считает вклад пользователей.

Бот не хранит сами изображения на сервере. Он сохраняет только Telegram `file_id` и `file_unique_id`, а физические файлы остаются на стороне Telegram.

## Главная идея

- в группах бот раздаёт пикчи, запускает дуэли, показывает статы и топ
- загрузка пикч идёт только в личке с ботом, чтобы Telegram Privacy Mode не ломал приём файлов
- пул общий: загрузили в личке, используете в любой группе
- данные живут в нормализованной SQLite-базе, старые `image_pool.json` и `jokes.json` автоматически подхватываются при миграции
- дубликаты пикч отсекаются по `file_unique_id` и быстрому fallback по `file_id`
- текстовые баяны отсекаются по нормализованному тексту без лишней пунктуации
- визуальные дубли можно чистить отдельным скриптом через `dHash`
- тяжёлые зависимости для визуальной чистки вынесены в отдельный maintenance-файл
- один пользователь может добавить до `1000` новых пикч в час
- один пользователь может поставить одну реакцию на картинку, но может перевыбрать
- `2 🖕🏻` удаляют пикчу или анекдот из пула народным судом
- топ и достижения показывают username без `@`, чтобы никого не тегать
- дуэли разделены по аренам: одна пикчевая и одна анекдотная могут идти одновременно
- турнир пикч идёт отдельным режимом: 4 пикчи, 90 секунд, один чемпион, без удаления
- дуэли не зависают навсегда: таймер обновляется, stale-состояния очищаются

## Команды

Публичное меню команд держится коротким: только то, что нужно запускать руками чаще всего.

| Команда | Что делает |
| --- | --- |
| `/start` | Запустить картинный реактор |
| `/menu` | Открыть главный пульт |
| `/pic` | Выдать случайную пикчу со склада |
| `/joke` | Достать случайный анекдот из блокнота |
| `/duel` | Устроить дуэль двух пикч |
| `/jokeduel` | Устроить дуэль двух анекдотов |
| `/tournament` | Запустить турнир четырёх пикч |
| `/weather` | Показать погоду Малой Токмачки |
| `/upload_pidor` | Принять пикчи в личке |
| `/upload_joke` | Принять анекдоты в личке |
| `/stats` | Показать сводку склада и арен |
| `/me` | Открыть личную карточку игрока |
| `/top` | Показать топ поставщиков пикч |
| `/help` | Показать карту команд |

`/upload` намеренно нет. Slash-команды загрузки явные: `/upload_pidor` для пикч и `/upload_joke` для анекдотов.

Работают, но не торчат в публичном меню:

- `/done` - завершить текущую загрузку
- `/cancel` - отменить текущую загрузку
- `/count` - быстрый счётчик пикч и анекдотов

Скрытые служебные команды:

- `/reset_stats` - сброс реакций, показов, дуэлей и памяти рандома, только для `ADMIN_USER_IDS`
- `/dedupe_user USER_ID` - чистка точных дублей конкретного пользователя, только для `ADMIN_USER_IDS`
- `/id` - показать Telegram user ID, не отображается в публичном меню команд

## Рандом

Рандом не выбирает тупо первый попавшийся элемент. Алгоритм:

1. Убирает картинки, недавно показанные в текущем чате.
2. Убирает глобально свежие выдачи, чтобы пул не ходил по одному кругу.
3. Предпочитает окно из наименее показанных записей, а не один жёсткий минимум.
4. Финально выбирает взвешенно через `SystemRandom`: меньше показов — выше шанс.

Если пул большой, повторы становятся заметно реже. Если пул маленький, повторы возможны, но бот старается не крутить одну и ту же пикчу подряд.

Дуэли используют отдельную историю арены: две пикчи из только что сыгранной пары не должны сразу же собраться в новую пару.

Турнир использует отдельную историю `tournament:{chat_id}` и выбирает четыре менее замученные выдачами пикчи.

Анекдоты используют такую же идею: бот хранит историю выдачи по чату, выбирает из окна менее показанных записей и не тащит один и тот же текст подряд, если в пуле есть выбор.

## Погода

`/weather` и кнопка `🌦 Погода` показывают текущую погоду только для Малой Токмачки.

Погодные данные берутся без API-ключа. Пользователь ничего не выбирает и не вводит город.

Ответ оформлен отдельной карточкой: температура, ощущается, состояние неба, дневной коридор, осадки, ветер и короткий вердикт. Чтобы бот не дёргал внешний API на каждый клик, погода кэшируется на `10` минут.

## Анекдоты

`/joke` и кнопка `😂 Анекдот` отправляют случайный текст из отдельного пула.

Как загрузить:

1. Откройте личку с `@kartinkomet_bot`.
2. Нажмите `📬 Загрузка`, затем `📝 Анекдоты`, или отправьте `/upload_joke`.
3. Отправляйте анекдоты текстом, по одному сообщению на штуку.
4. Завершите через `/done` или отмените через `/cancel`.

Правила:

- анекдоты хранятся отдельно от пикч в SQLite-таблицах `jokes`, `joke_reactions` и `joke_chat_history`
- картинки и анекдоты не смешиваются
- пустые сообщения и команды не добавляются
- дубли отсекаются по нормализованному тексту
- один пользователь может поставить одну реакцию, но может перевыбрать
- `2 🖕🏻` удаляют анекдот из пула
- `/reset_stats` обнуляет реакции, показы и память выдачи, но не удаляет сами анекдоты

## Дуэли анекдотов

`/jokeduel` и кнопка `🥊 Шутко-бой` выбирают два случайных анекдота и открывают голосование на `2` минуты.

Правила такие же, как у пикчевой арены:

- в одном чате может идти одна активная дуэль анекдотов
- пикчевая дуэль может идти параллельно с анекдотной
- каждый пользователь голосует один раз, но может перевыбрать сторону
- тексты анекдотов отправляются отдельными цитатами перед голосованием
- анекдоты не обрезаются: длинный текст дробится на несколько сообщений, но сохраняется полностью
- победитель остаётся в пуле анекдотов
- проигравший анекдот удаляется из пула
- при ничьей оба анекдота остаются
- после итогов появляется кнопка `🥊 Реванш шуток`

## Загрузка пикч

Надёжный сценарий:

1. Откройте личку с `@kartinkomet_bot`.
2. Нажмите `📬 Загрузка`, затем `📥 Пикчи`, или отправьте `/upload_pidor`.
3. Отправьте одну пикчу, пачку, альбом или пересланные изображения.
4. Нажмите `✅ Закончить` или отправьте `/done`.

В группе кнопка `📬 Загрузка` не включает приём файлов. Она объясняет, что заливать нужно в личке.

Бот не пишет отбивку на каждую картинку. Инструкция и кнопки завершения показываются сразу при старте загрузки, а дальше бот молча считает результат.

Учитываются:

- успешно добавленные пикчи
- дубликаты
- невалидные файлы
- лимит `1000` новых пикч в час на пользователя

## Дуэли

`/duel` выбирает две случайные пикчи, отправляет их альбомом без подписей и открывает голосование на `60` секунд.

Правила:

- в одном чате может идти одна активная дуэль пикч
- анекдотная дуэль может идти параллельно с пикчевой
- каждый пользователь голосует один раз, но может перевыбрать сторону
- карточка дуэли обновляет счёт и таймер
- победитель остаётся в пуле
- проигравшая пикча удаляется
- при ничьей обе пикчи выживают
- после итогов появляется кнопка `⚔️ Реванш пикч`
- если Telegram/API споткнулся, бот очищает зависшую дуэль и не блокирует чат

Карточка дуэли держит короткую структуру: заголовок, статус, счёт в одну строку и отдельный таймер. Картинки в альбоме идут без подписей, чтобы экран не превращался в кашу.

Внутри есть `600` коротких фраз для пикчевых дуэлей:

- `150` заголовков старта
- `150` live-статусов
- `150` фраз победы
- `150` фраз ничьи

## Турниры

`/tournament` и кнопка `🏟 Турнир` выбирают четыре случайные пикчи и запускают голосование на `90` секунд.

Турнир отличается от дуэли:

- он не удаляет проигравших
- он выбирает чемпиона витрины
- каждый пользователь голосует один раз, но может перевыбрать вариант
- если несколько пикч набрали максимум или голосов нет, чемпион не назначается
- после финала появляется кнопка `🏟 Новый турнир`

Идея простая: дуэль — народный суд, турнир — шоу-витрина.

## Реакции и народный суд

Под каждой пикчей есть `🤙🏻` и `🖕🏻`.

Правила:

- один пользователь = один голос на одну картинку
- голос можно изменить
- голоса разных пользователей складываются
- повторное нажатие той же реакции не накручивает счётчик

Народный суд:

- `1 🖕🏻` - бот молчит
- `2 🖕🏻` - пикча или анекдот удаляется из пула, сообщение об удалении отправляется ответом на исходное сообщение

## Достижения и профиль

`/me` показывает:

- сколько пикч загрузил пользователь
- текущее достижение
- реакции на его пикчи
- показы его пикч
- титул качества
- комбо-достижения
- прогресс до следующего рубежа

Достижения выдаются автоматически на порогах загрузки. В сообщениях username пишется без `@`, чтобы не тегать человека.

## Текстовые пулы

Все фразы лежат в `bot/texts.py`.

Сейчас внутри:

- `1550` caption-фраз для случайных пикч
- `200` стартовых фраз загрузки
- `200` фраз завершения загрузки
- `200` фраз пустого пула
- `100` достижений
- `600` коротких фраз для пикчевых дуэлей
- по `80` фраз на каждый этап дуэлей анекдотов
- по `80` фраз на каждый этап турниров
- тексты народного суда

Caption под пикчами чистый, без лишних приставок.

## Хранение

Основное хранилище — SQLite-файл `kartinkomet.sqlite`.

Внутри база разложена по нормальным таблицам, а не хранит весь пул одним большим JSON:

- `images` — пикчи, Telegram `file_id`, `file_unique_id`, счётчики показов и реакции
- `image_reactions` — один голос одного пользователя на одну пикчу
- `image_chat_history` — память рандома по чатам
- `image_stats` — дуэли, турниры и версия схемы
- `users` — username и имя для топа без Telegram-пингов
- `jokes` — анекдоты и их счётчики
- `joke_reactions` — реакции на анекдоты
- `joke_chat_history` — память выдачи анекдотов

Старый формат не выбрасывается. Если SQLite ещё пустой, бот сначала пробует старый `documents`-формат внутри SQLite, затем старые `image_pool.json` и `jokes.json`, нормализует данные и записывает их уже в таблицы. Переезд проходит без ручного импорта.

JSON ниже — совместимая форма миграции и локального fallback-режима без `DATABASE_PATH`.

Пример:

## Производительность и надёжность

- пул читается в память один раз при запуске
- SQLite используется как основной стабильный файл хранения с отдельными таблицами для пикч, анекдотов, реакций, истории и пользователей
- старые JSON-файлы используются как источник первой миграции
- поиск картинки по `id` работает через индекс
- проверка дублей по `file_unique_id` и `file_id` работает через set
- текстовые баяны нормализуются по регистру, пробелам и пунктуации
- `/stats`, `/top` и `/me` используют in-memory кэш и инвалидируются только после изменений пула
- рандом выбирает из окна least-shown кандидатов через heap, без полной сортировки пула
- дуэли используют общую историю арены, чтобы свежая пара не повторялась сразу
- активные дуэли хранятся в двух слотах на чат: `image` и `joke`
- дубль блокируется только внутри своего слота, поэтому пикчевая и анекдотная арены не мешают друг другу
- счётчики загрузок пользователей берутся из индекса
- статистика пользователя берётся из индекса записей по user ID
- лимит загрузок в час считается по отсортированному индексу времени
- лимит загрузок `1000` в час отделён от достижений: антиспам не двигает игровые титулы
- пары для дуэлей и четвёрки для турниров выбираются отдельными методами и сохраняют показы одной операцией
- активная дуэль анекдотов хранит только `id`, голоса и таймер, а не полный текст анекдотов
- длинные анекдоты дробятся по HTML-safe размеру сообщения и не режутся по смыслу
- `Pillow` не входит в боевые зависимости Railway и нужен только maintenance-скрипту
- реакции нормализуются при чтении базы
- запись в SQLite идёт через нормализованный storage-слой с обратной совместимостью для старых документов
- JSON-запись остаётся только как fallback для тестов и ручного локального режима без `DATABASE_PATH`
- завершение дуэли пикч удаляет проигравшую пикчу и пишет статистику одним сохранением
- завершение дуэли анекдотов удаляет проигравший текст из базы
- завершение турнира пишет статистику, но не удаляет пикчи
- stale-дуэли очищаются при следующей попытке запуска
- лишние Telegram-редакты счёта дуэлей пропускаются, а `message is not modified` не засоряет логи
- отправка альбомов и карточек дуэлей переживает короткие сетевые сбои Telegram через retry и fallback на отдельные фото
- ошибки Telegram API логируются и не роняют polling

## Чистка дублей

Точные дубли конкретного пользователя:

```text
/dedupe_user 1045485205
```

Визуальные дубли через maintenance-скрипт:

```bash
pip install -r requirements-maintenance.txt
python scripts/visual_dedupe.py --user-id 1045485205 --dry-run
```

Применить после проверки отчёта:

```bash
python scripts/visual_dedupe.py --user-id 1045485205 --apply
```

Скрипт создаёт backup рядом с `image_pool.json`. Запускать лучше разово на Railway и не во время активного наплыва пользователей.

## Локальный запуск

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

`.env`:

```env
BOT_TOKEN=123456:your-token
DATABASE_PATH=data/kartinkomet.sqlite
IMAGE_POOL_PATH=data/image_pool.json
JOKE_POOL_PATH=data/jokes.json
TARGET_CHANNEL_ID=
ADMIN_USER_IDS=
```

Запуск:

```bash
python -m bot
```

Проверки:

```bash
python -m compileall bot scripts tests
python -m unittest discover
```

Для визуальной чистки дублей дополнительно:

```bash
pip install -r requirements-maintenance.txt
```

## Railway

В проекте есть:

- `Procfile` - запускает `python -m bot`
- `.python-version` - Python `3.12`

Railway variables:

```env
BOT_TOKEN=токен_бота
TARGET_CHANNEL_ID=
ADMIN_USER_IDS=ваш_telegram_user_id
```

Для постоянного хранения подключите Railway Volume с mount path:

```text
/data
```

Если `RAILWAY_VOLUME_MOUNT_PATH` есть, бот хранит основную базу тут:

```text
/data/kartinkomet.sqlite
```

Если рядом уже лежат старые файлы `/data/image_pool.json` и `/data/jokes.json`, они будут использованы для первой миграции.

bot/keyboards.py   # inline-клавиатуры
bot/storage.py     # SQLite storage: таблицы, миграция и legacy fallback

scripts/           # разовые maintenance-скрипты
tests/             # контрактные тесты
requirements.txt   # боевые зависимости бота
requirements-maintenance.txt # зависимости для тяжёлых разовых скриптов
