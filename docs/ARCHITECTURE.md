# Архитектура kartinkomet

## Слои

```
Telegram ──► bot/tg/*  ──► bot/game.py ──► bot/core/*   (правила, без I/O)
                 │               │
                 ▼               ▼
            bot/texts/*     bot/db/repo.py ──► SQLite (WAL)
```

| Слой | Что можно | Чего нельзя |
| --- | --- | --- |
| `core/` | Чистые функции: колода, Elo, исход боя, вердикт суда, ачивки | Импортировать aiogram, ходить в базу |
| `db/repo.py` | Весь SQL | Знать про Telegram и правила игры |
| `game.py` | Связывать правила и базу, возвращать результаты (`BattleReport`, `CourtReport`…) | Отправлять сообщения |
| `tg/` | Принимать апдейты, рисовать карточки, отправлять сообщения | Писать SQL, решать исход боя |
| `texts/` | Фразы и `pick()` с анти-повтором | Логику |

Зависимости в обработчики приходят через workflow data диспетчера: `game`, `live`, `admins`.

## Данные

Схема — [bot/db/schema.sql](../bot/db/schema.sql). Время везде в unix-секундах UTC.

- **pics**: пикча никогда не удаляется физически. `status` = `alive` / `executed` / `deleted`, плюс `removed_reason` (`duel`, `court`, `admin`). Здесь же рейтинг, бои, победы, поражения, `loss_streak`, `best_streak`, иммунитет.
- **deck_seen**: какие пикчи уже показаны в текущем круге колоды. Скоупы: `pic:<chat>` для рандома, `arena:<chat>` для боёв.
- **battles / battle_entries / battle_votes**: дуэли и турниры, включая активные. Таймеры переживают рестарт.
- **courts / court_votes**: суды, последнее слово, сообщение с пикчей, на которой висят кнопки.
- **achievements**, **meta** (рекорды серий, счётчики, отметки миграции), **panels** (живая панель на чат).

## Ключевые потоки

**Рандом.** `deck.draw_one` бросает кубик 70/20/10, берёт случайную живую пикчу, не показанную в этом скоупе, и отмечает её показанной. Если показаны все, `deck_seen` скоупа очищается: начинается новый круг.

**Реакция → суд.** `Game.react` пишет реакцию. Если дизлайков стало ровно 2 (или 4, 6…), нет иммунитета и нет активного суда, то `court_due=True`. Тогда `tg/court.open_court` создаёт суд, отправляет карточку-фото ответом на пикчу и меняет кнопки пикчи на «⚖️ Идёт суд».

**Бой.** `Game.start_duel` создаёт запись боя ещё до отправки альбома. Поэтому второй клик в ту же секунду увидит активный бой и не запустит второй. Если Telegram не принял альбом, бой удаляется. `Live` раз в 15 секунд обновляет карточку, а по таймеру вызывает `Game.finish_battle`. Закрытие атомарное (`UPDATE … WHERE status='active'`), так что двойного финала не бывает.

**Чемпион.** Кнопка «👑 Чемпион дальше» несёт id боя. Она работает, только если этот бой — последняя дуэль чата (`meta last_duel:<chat>`). Старые кнопки отвечают «уже не актуально».

**Голоса.** Голос пишется сразу, а карточка перерисовывается не чаще раза в 1.5 секунды (`Live.request_refresh_*`): Telegram ограничивает частоту правок в чате.

**Самовосстановление.** Если таймер боя или суда умер, а запись осталась активной, следующий запуск дуэли или суда сначала досчитает зависший и только потом начнёт новый.

**Кнопки v1.** Реакции `react:like|dislike:<id>` под старыми сообщениями переводятся в v2: id пикч при миграции сохранены. Остальные старые кнопки отвечают «жми /menu».

**Рестарт.** `Live.restore()` поднимает таймеры всех активных боёв и судов. Просроченные финализируются сразу.

**Миграция v1 → v2.** `migrate_if_needed` открывает v1 только на чтение, строит v2 во временном файле, сверяет количество пикч, реакций и юзеров и только потом переименовывает. Стартовый рейтинг: `1000 ± 15 × (лайки − дизлайки)`, в пределах ±150. Ачивки за уже сделанное выдаются при первом старте молча (`backfill_achievements`), чтобы не заспамить чат.

## Инварианты

- `callback_data` ≤ 64 байт (проверяется в `tests/test_bot.py`).
- Все фразы уникальны, без символов `<>&{}` (проверяется в `tests/test_texts.py`).
- Казнённая пикча никогда не выпадает в рандоме и на арене.
- Суд на одну пикчу — один одновременно.
- База v1 не модифицируется.
